# ProFootball Design System

A living reference for the app's UI tokens. Every token, decision, and
convention in this document maps directly to `src/app/globals.css`. When
the CSS changes, update this file — they should always agree.

---

## 1. Principles

**Token-first.** No raw hex/oklch values or pixel radii in component code.
Everything comes from a named token exposed as a Tailwind utility
(`bg-background`, `rounded-lg`, `text-destructive`, ...).

**No circular references.** Raw values live in `:root` under one name
(e.g. `--background`). The `@theme inline` block maps them to a
Tailwind-consumable name (e.g. `--color-background`). This is what makes
dark mode token swaps work.

**Dark mode by default.** Every color token has a `.dark` override. When
adding a new token that will change in dark mode, add its override at the
same time — not later.

**No `bg-white`.** Use `bg-background` (maps to `--background`). The
distinction matters: `--background` swaps in dark mode, `white` never does.

---

## 2. File structure

```
globals.css
├── @theme inline    Tailwind mapping layer — connects tokens to utility
│                    classes like bg-background, text-foreground, rounded-lg
├── :root            Raw oklch tokens — background, foreground, card,
│                    popover, primary, secondary, muted, accent,
│                    destructive, border, input, ring, chart, sidebar, radius
├── .dark            Dark mode overrides for every token above
└── @layer base      box-sizing/border defaults, body background+foreground,
                     html font-sans
```

Components are generated by shadcn (style: `base-nova`, base color:
`neutral`) on top of `@base-ui/react` primitives, then customized in
`components/ui/`.

## 3. Color

There is no custom brand palette — the token set is shadcn's default
neutral scale, defined as oklch values with a light/dark pair for each
role.

| Token                    | Usage                                          |
| ------------------------ | ----------------------------------------------- |
| `--color-background`     | Page background                                 |
| `--color-foreground`     | Default text color                              |
| `--color-card`           | Card surface (`Card` component)                 |
| `--color-popover`        | Dialog/popover surface                          |
| `--color-primary`        | Primary button/action                           |
| `--color-secondary`      | Secondary surfaces, finished-match badge        |
| `--color-muted`          | Muted backgrounds, secondary text                |
| `--color-accent`         | Hover/expanded states                           |
| `--color-destructive`    | Errors — and doubled as the **live match** accent |
| `--color-border`         | Default border                                  |
| `--color-input`          | Input border                                    |
| `--color-ring`           | Focus ring                                      |

**Tailwind utilities:** `bg-background`, `text-foreground`, `border-border`, `text-destructive`, etc.

`--chart-1` … `--chart-5` and `--sidebar*` tokens exist in `globals.css`
(part of the shadcn scaffold) but nothing in the app uses them yet — there
is no chart or sidebar layout. Don't build against them until a component
actually needs them.

### 3.1 Live-match convention

There's no dedicated "status color" token set. Match status is expressed
by reusing existing semantic tokens and `Badge`/`Card` variants:

| Status    | Badge variant | Card treatment                  |
| --------- | ------------- | -------------------------------- |
| Live      | `destructive` | `ring-destructive/25`, animated `LiveIndicator` bar |
| Upcoming  | `outline`     | —                                 |
| Finished  | `secondary`   | —                                 |

See `components/shared/matches/live-indicator.tsx` and `components/shared/matches/match-row.tsx`.

## 4. Typography

### 4.1 Fonts

Two typefaces, loaded via `next/font/google` in `app/layout.tsx` and
mapped in `@theme inline`:

| Variable            | Typeface       | Tailwind        | Usage                                  |
| -------------------- | -------------- | ---------------- | ---------------------------------------- |
| `--font-oswald`      | Oswald         | `font-heading`   | Headings, badges, scores, labels        |
| `--font-source-sans` | Source Sans 3  | `font-sans`      | Body copy (the `html` default)          |

### 4.2 Display text utility

Headings, status badges, and match minutes share one look: uppercase,
wide-tracked heading font. Rather than a type scale, this is a shared
constant:

```ts
// src/utils/typography.ts
export const DISPLAY_TEXT_CLASS = "font-heading uppercase tracking-[0.16em]";
```

```tsx
<h1 className={cn(DISPLAY_TEXT_CLASS, "text-2xl text-foreground")}>
  Match Centre
</h1>
```

There is no other custom type scale — use Tailwind's default `text-*`
sizes and `font-normal`/`font-medium`/`font-semibold` weights directly.

---

## 5. Spacing & layout widths

No custom spacing or content-width tokens are defined. Pages use
Tailwind's default spacing scale and arbitrary `max-w-*` values directly
(e.g. `max-w-6xl` in `app/page.tsx`). Don't add spacing tokens unless a
value repeats across multiple components and the default scale can't
express it.

---

## 6. Border radius

The one real customization on top of shadcn defaults — every step derives
from a single `--radius` base (`0.5rem` / 8px):

| Utility        | Formula          | Value | Usage                        |
| -------------- | ----------------- | ----- | ------------------------------ |
| `rounded-sm`   | `radius * 0.6`     | 4.8px | Small controls                 |
| `rounded-md`   | `radius * 0.8`     | 6.4px | Inputs, small buttons           |
| `rounded-lg`   | `radius`           | 8px   | Default — buttons, cards        |
| `rounded-xl`   | `radius * 1.4`     | 11.2px | Match cards                    |
| `rounded-2xl`  | `radius * 1.8`     | 14.4px | —                              |
| `rounded-3xl`  | `radius * 2.2`     | 17.6px | —                              |
| `rounded-4xl`  | `radius * 2.6`     | 20.8px | Pill-shaped badges             |

Changing the look of the whole app's roundedness means changing
`--radius` once in `:root` — not each individual `rounded-*` usage.

---

## 7. Shadows

No custom shadow tokens — Tailwind's default `shadow-*` scale is used
as-is where needed (e.g. dialogs). Don't add shadow tokens without a
repeated, non-default value to justify them.

---

## 8. Buttons

`components/ui/button.tsx` wraps `@base-ui/react/button` with `cva`
variants. All variants share the same base treatment (rounded-lg,
`font-heading`, uppercase, wide tracking):

| Variant       | Usage                          |
| ------------- | -------------------------------- |
| `default`     | Primary action                    |
| `outline`     | Secondary action                  |
| `secondary`   | Alternate surface                 |
| `ghost`       | Low-emphasis / icon buttons       |
| `destructive` | Destructive action                |
| `link`        | Inline text action                 |

Sizes: `default`, `xs`, `sm`, `lg`, `icon`, `icon-xs`, `icon-sm`, `icon-lg`.

```tsx
<Button variant="default" size="default">
  Refresh
</Button>
```

Don't hand-roll button styles — add a variant to `buttonVariants` if an
existing one doesn't fit.

---

## 9. Dark mode

Dark mode is activated by adding the `.dark` class to an ancestor element
(`@custom-variant dark (&:is(.dark *))`). All semantic tokens
(`--color-background`, `--color-foreground`, `--color-border`, etc.)
resolve to their dark oklch values automatically.

**Rules:**

- Never use `bg-white` or a raw hex/oklch value in components — use the semantic token (`bg-background`, `text-foreground`, etc.)
- Every color token needs a `.dark` override in `globals.css`
- There is no dark-mode toggle wired up in the UI yet — the class simply isn't applied anywhere at runtime today

---

## 10. Adding new tokens — checklist

Before writing a component with a hardcoded value, ask:

1. Does this value already exist as a token? Search `globals.css` first.
2. Does this value repeat in more than one place? If yes, it needs a token.
3. Is it a one-off internal value? If yes, an arbitrary Tailwind value (e.g. `gap-[7px]`) is acceptable — don't add single-use tokens.
4. Add the raw value to `:root` with a plain name (matching the existing convention, e.g. `--background`).
5. Map it in `@theme inline` under the Tailwind-consumable name (`--color-*`, `--radius-*`, `--font-*`).
6. If it changes in dark mode, add the override to `.dark`.
7. Update this document.
